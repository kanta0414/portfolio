## 1. 背景と目的

### 1.1 背景
株式会社LayerX Ai Workforce事業部「Forward Deployed Engineer（FDE）実務インターン」への応募にあたり、
書類・面談だけでは伝わりにくい実装力とLLM領域の取り組みを、選考担当者が短時間で判断できる形で提示する。

### 1.2 目的（ゴール）
1. **技術的信頼の獲得** — Python×LLMの実装・評価経験を提示し、TypeScript/Reactの実装力は**サイト自体の完成度で証明する**
2. **カルチャーフィットの提示** — 「Be Animal / Bet AI」に接続する、手を動かした証拠を見せる
3. **次アクションへの誘導** — 各作品のGitHub READMEおよび連絡先への導線を最短にする

### 1.3 非目標
- 不特定多数向けの集客・SEO最大化（読者は特定少数）
- サイト上での技術詳細の網羅（→ 各リポジトリのREADMEに委譲。§4.3）
- CMS・問い合わせフォーム・多言語対応


## 4. 機能要件

### 4.1 ページ構成

| ID | ページ | パス | 優先度 | 内容 |
|----|--------|------|--------|------|
| F-01 | トップ | `/` | Must | IDEレイアウト。初期表示はプロフィール（`about.md`）を開いた状態 |
| F-02 | 作品ページ | `/works/[slug]` | Must | ツリーから選択。§4.3のテンプレートに準拠 |
| F-03 | About | `/about` | Must | 自己紹介、経歴、スキル。トップの初期表示と同一内容 |
| F-04 | Contact | `/contact` | Must | GitHub / メール / X。ページというよりパネル1枚 |
| F-05 | Notes | `/notes/[slug]` | Could | 技術ログ。初期リリース対象外。ツリーに `notes/` を足すだけで拡張可能 |
| F-06 | 404 | - | Should | 「file not found」のIDE風表現 |

> ページ遷移はURLを持つ（共有・直リンク・戻るボタンが機能すること）。SPA的にパネルだけ差し替える見た目でも、ルーティングは実URLで行う。

### 4.2 IDEレイアウトの構成要素

| ID | 要素 | 優先度 | 仕様 |
|----|------|--------|------|
| L-01 | タイトルバー | Must | 信号機ボタン（装飾）、中央に `kanta — portfolio` |
| L-02 | サイドバー（ファイルツリー） | Must | `works/` 配下に作品、`about.md`、`contact.md`、外部リンク。現在ファイルをハイライト |
| L-03 | タブバー | Should | 開いた作品をタブ表示。複数タブは**最大3枚**まで、それ以上は古い順に閉じる |
| L-04 | エディタ領域 | Must | 行番号 + Markdown風の本文。見出し・強調・リンクに構文色を付ける |
| L-05 | プレビュー画像 | Must | 本文中に作品スクリーンショットを埋め込む（作品を見せる主役） |
| L-06 | ステータスバー | Should | `main*` / `N works` / `Markdown` などの表示（装飾） |

### 4.3 作品ページのコンテンツ（★情報量を絞る）
サイト上は**入口**に徹し、技術構成・設計判断・試行錯誤はREADMEに委譲する。

```
1. タイトル      : リポジトリ名
2. 概要         : 1〜2文。何を解決するものか
3. スクリーンショット : 1〜2枚（作品そのものを見せる）
4. 数字         : 1〜2個のみ（例: 抽出精度 92%）
5. 担当範囲      : "個人開発" / "3人チーム・バックエンド担当" など一行
6. タグ         : LLM / Python / React 等、3つまで
7. リンク       : README（必須）/ デモ / 記事
```

**サイトに載せないもの**: システム構成図、技術選定の比較検討、ディレクトリ構成、セットアップ手順、学び・反省。すべてREADMEに書く。

> 「担当範囲」と「数字」だけはREADMEに逃さずサイトに残す。READMEは開発者向けに書かれており、
> 一覧段階で判断する読み手（P2）はクリックして読み下すところまで到達しないため。

### 4.4 共通機能

| ID | 機能 | 優先度 | 備考 |
|----|------|--------|------|
| F-10 | レスポンシブ対応 | Must | §7.5の分岐仕様に従う |
| F-11 | OGP / メタタグ | Must | ページ単位。IDE画面のOG画像 |
| F-12 | ダークモード | Must | **ダーク固定**。ライトテーマは提供しない（IDE表現の一貫性を優先） |
| F-13 | 外部リンク | Must | GitHub / メール / X |
| F-14 | キーボード操作 | Should | `↑↓` でツリー移動、`Enter` で開く |
| F-15 | アクセス解析 | Could | Vercel Analytics |

## 6. 技術構成

| レイヤ | 技術 | 理由 |
|--------|------|------|
| フレームワーク | **Next.js 15（App Router）** | 応募先スタックと一致。SSG / OGP / 画像最適化 |
| 言語 | **TypeScript**（strict, `any` 禁止） | 型安全性 |
| スタイリング | **Tailwind CSS** | IDEカラーをトークン化して一元管理 |
| コンテンツ | **MDX**（`content/works/*.mdx`） | ファイル＝作品。ツリー構造と1:1で対応し、メタファと実装が一致する |
| スキーマ検証 | Zod（frontmatter） | 必須項目の入れ忘れ防止 |
| シンタックスハイライト | Shiki | エディタ領域の構文色。VS Code と同じエンジン |
| アニメーション | CSS transition 中心 | パネル切替のみ。ライブラリは原則不要 |
| ホスティング | Vercel | PRプレビュー |
| CI | GitHub Actions | lint / typecheck / build |

### 6.1 ディレクトリ構成
```
portfolio/
├─ src/
│  ├─ app/
│  │  ├─ layout.tsx          # IDEシェル（タイトルバー/サイドバー/ステータスバー）
│  │  ├─ page.tsx            # = about を開いた状態
│  │  ├─ works/[slug]/page.tsx
│  │  └─ contact/page.tsx
│  ├─ components/
│  │  ├─ ide/                # TitleBar, FileTree, TabBar, EditorPane, StatusBar
│  │  ├─ ui/                 # Tag, MetricBadge, LinkButton
│  │  └─ mdx/                # MDXコンポーネントのマッピング
│  ├─ lib/                   # content loader, schema, tree builder
│  └─ styles/
├─ content/works/*.mdx
├─ public/screenshots/
└─ docs/
   ├─ requirements.md
   └─ design/*.svg
```

### 6.2 データモデル
```ts
type Work = {
  slug: string;              // = ファイル名 = ツリー表示名
  title: string;
  summary: string;           // 1〜2文
  role: string;              // "個人開発" 等
  tags: string[];            // 最大3
  metrics: { label: string; value: string }[];  // 最大2
  screenshots: string[];     // 1〜2枚
  links: { readme: string; demo?: string; article?: string };  // readme必須
  order: number;             // ツリー内の並び順
};
```

## 7. デザイン仕様（B-3「IDE」案）

### 7.1 コンセプト
VS Code / GitHub のエディタ画面をモチーフに、**ファイルツリーから作品を開く**構成。

採用理由:
- **作品が少なくても成立する** — ツリーは2ファイルでも自然に見える（グリッドは3件未満で破綻する）
- **「詳細はREADME」という方針と構造が一致** — Markdownを開いている画面なので、簡潔な本文が不自然でない
- **一目で技術者だと伝わる** — 第一印象で職種が確定する
- **コードで表現する対象がUIそのもの** — 実装力の証明が成果物と一体になる

### 7.2 カラートークン（ダーク固定）
| 用途 | 値 |
|------|-----|
| 背景（エディタ） | `#0D1117` |
| 背景（サイドバー / タイトルバー） | `#0A0E13` |
| 罫線 | `#1C2530` |
| 本文 | `#E6EDF3` |
| 副次テキスト | `#8B949E` |
| 行番号 / 最弱 | `#3D4753` |
| アクセント（リンク） | `#58A6FF` |
| アクセント（数値・強調） | `#7EE787` |
| アクティブタブ下線 | `#F78166` |
| 選択行の背景 | `#152030` |

### 7.3 タイポグラフィ
| 用途 | フォント |
|------|---------|
| UI全般（ツリー・タブ・ステータス） | 等幅（`ui-monospace`, SF Mono, Menlo） |
| 本文（作品説明の日本語） | サンセリフ（Inter + Noto Sans JP）※等幅の日本語は可読性が落ちるため |
| 見出し（`# title`） | 等幅、`#` 記号を淡色で残す |

### 7.4 主要インタラクション
| 動作 | 挙動 |
|------|------|
| ツリーの項目をクリック | エディタ領域を差し替え、タブを追加、URLを更新 |
| ツリーのホバー | 行背景を `#11161D` に |
| タブの × | タブを閉じ、直前のタブへ |
| サイドバーのトグル | 常設サイドバーを畳む / 戻す。既定は展開。アニメーションなし |
| 外部リンク | 新規タブで開く（ツリー内は `↗` を付けてサイト内と区別） |
| パネル切替 | 80ms のフェードのみ。派手な演出はしない |

### 7.5 レスポンシブ分岐（★最重要）
IDE比喩はモバイルで成立しないため、明確に分岐させる。

| 幅 | レイアウト |
|----|-----------|
| **768px以上** | フルIDE。サイドバー常設 + エディタの2ペイン。サイドバー幅は 1024px以上で 280px、768〜1023px で 240px（あわせて行番号ガターを 72px → 48px に詰める）。タイトルバーのトグルで畳める（既定は展開） |
| **767px以下** | **IDE比喩を放棄**。タイトルバーとステータスバーのみ残し、通常の縦積み1カラム（作品リスト → 詳細）。ツリーはページ下部の一覧に変換 |

> 767px以下で無理にツリーを残すと、ただ使いにくいだけになる。「モバイルではIDEをやめる」を明示的な仕様とする。
> 一方 768px 以上では、モチーフである VS Code の「左にツリーが常駐し、選んだファイルの中身が右に出る」構造を
> 優先し、オーバーレイではなく常設とする。経緯と寸法の根拠は [requirements-sidebar.md](./requirements-sidebar.md)。

### 7.6 アクセシビリティ要件（IDE比喩の副作用対策）
- ファイルツリーは `<nav>` + `<ul>/<li>` + `<a>` で実装する。`div` + `onClick` は禁止
- タブバーは装飾扱い。**タブがなくても全ページに到達できる**こと
- 行番号は `aria-hidden="true"`（スクリーンリーダーが数字を読み上げないように）
- 信号機ボタン・ステータスバーは装飾。`aria-hidden` かつフォーカス不可
- フォーカスリングを消さない。`#58A6FF` の2px outline を全インタラクティブ要素に
- 本文と背景のコントラスト比 4.5:1 以上（`#8B949E` on `#0D1117` = 約7.2:1 でクリア）

### 7.7 このデザインのリスクと対策
| リスク | 対策 |
|--------|------|
| ギミックが先行して中身が薄く見える | 本文の情報量（§4.3）を落とさない。数字を必ず1つ以上入れる |
| 「VS Codeのパクリ」に見える | 配色をGitHub Dark寄りにし、VS Codeの既定色そのままは避ける。ロゴ・アイコンは流用しない |
| モバイルで破綻 | §7.5で比喩を放棄する分岐を明記 |
| 実装コストの膨張 | タブバー（L-03）とキーボード操作（F-14）はShould。間に合わなければ落とす |

## 8. 開発フェーズ

| Phase | 内容 | 完了条件 |
|-------|------|---------|
| 0 | 要件・デザイン確定 | 本ドキュメント承認 ✅ |
| 1 | 環境構築 | Next.js + TS + Tailwind 初期化、Vercel デプロイ疎通 |
| 2 | IDEシェル実装 | TitleBar / FileTree / EditorPane / StatusBar が静的データで表示される |
| 3 | MDX基盤 + 作品ページ | `content/works/*.mdx` 追加でツリーに自動反映。作品2件掲載 |
| 4 | About / Contact | 実コンテンツ投入 |
| 5 | レスポンシブ + A11y | §7.5 の3分岐、Lighthouse 90+ |
| 6 | 仕上げ | OGP、404、タブバー、キーボード操作、独自ドメイン |

**最小リリース（MVP）= Phase 4 まで。** Phase 5 はリリース必須、Phase 6 は余力次第。
