## 1. 背景と目的

### 1.1 背景

現行実装は requirements.md §7.5 に従い、768〜1023px でサイドバーを折りたたみ、ハンバーガーから
**オーバーレイ**として表示している。しかし 1024px をわずかに下回る幅（実機確認時は 1014px）では
ツリーが初期表示で見えず、開いてもコンテンツに覆いかぶさるため、モチーフである VS Code の
「左にツリーが常駐し、選んだファイルの中身が右に出る」という体験と食い違う。

### 1.2 目的

**PC 幅では、ツリーが左に常駐している状態を既定にする。** ファイルを選ぶと右のエディタが
差し替わる、という VS Code の基本構造を、ウィンドウ幅に関わらず崩さない。

### 1.3 非目標

- 767px 以下（スマホ）の挙動変更 — **現状を維持する**（§3.2）
- サイドバー幅のドラッグリサイズ
- キーボードショートカットによる開閉（§3.2 で理由を記載）
- ツリーの折りたたみ（`works/` ディレクトリの開閉）など、ツリー自体の機能追加

## 2. 現状と課題

| | 現状 | 課題 |
|---|------|------|
| 1024px 以上 | ツリー常設（280px） | なし。これが目標形 |
| 768〜1023px | ハンバーガー → オーバーレイ | **初期表示でツリーが見えない。開くとコンテンツを覆う** |
| 767px 以下 | 比喩を放棄、下部に一覧 | なし。物理的に妥当 |

なお「ファイルを選ぶと右に中身が出る」挙動自体は 1024px 以上で既に成立している。
本改修は表示幅の問題であり、ナビゲーションのロジック変更は伴わない。

## 3. スコープ

### 3.1 対象

| ID | 要件 | 優先度 |
|----|------|--------|
| S-01 | 768px 以上でサイドバーを常設し、初期状態を「展開」にする | Must |
| S-02 | オーバーレイ表示（暗幕・モーダル的なフォーカス制御）を廃止する | Must |
| S-03 | タイトルバーのボタンを、常設サイドバーの開閉トグルに作り替える | Must |
| S-04 | 768〜1023px でサイドバー幅とエディタのガター幅を詰め、本文幅を確保する | Must |
| S-05 | requirements.md §7.4 / §7.5 を実装に合わせて更新する | Must |

### 3.2 非対象（決定済み）

| 項目 | 決定 | 理由 |
|------|------|------|
| 767px 以下 | **現状維持** | 375px の画面で 240px のサイドバーを出すと本文が 135px しか残らず成立しない。requirements.md §7.5 の「モバイルではIDEをやめる」判断は引き続き有効 |
| `Cmd/Ctrl+B` での開閉 | 実装しない | Firefox では `Ctrl+B` がブックマークサイドバーに割り当てられており衝突する。F-14（キーボード操作）は Should であり、ここまで踏み込む必要はない |
| 開閉状態の永続化 | しない | localStorage から復元すると「展開で描画 → 畳む」のちらつきが出る。サイト内遷移では App Router がレイアウトを保持するため状態は維持され、リロード時に既定（展開）へ戻るだけで実害がない |

## 4. 機能要件

### 4.1 レイアウト分岐（§7.5 の置き換え）

| 幅 | サイドバー | ガター | 備考 |
|----|-----------|-------|------|
| **1024px 以上** | 常設 **280px** | 72px | 現状から変更なし |
| **768〜1023px** | **常設 240px** | **48px** | 本改修の対象範囲 |
| **767px 以下** | 非表示（下部の一覧に変換） | 非表示 | 変更なし |

寸法の根拠（1024px は実測、768px は同条件からの算出）:

| 幅 | サイドバー | 本文カラム |
|----|-----------|-----------|
| 1024px | 280px | 614px（実測） |
| 768px（変更後の値で算出） | 240px | 約 437px |

> 768px でサイドバーを 280px・ガターを 72px のまま常設すると本文カラムが約 360px まで痩せる。
> S-04 の切り詰めは常設化とセットで行うこと。

### 4.2 開閉トグル

| ID | 要件 | 優先度 |
|----|------|--------|
| T-01 | 既定は**展開**。初回表示でツリーが見えていること | Must |
| T-02 | タイトルバーのボタンで展開 / 折りたたみを切り替える | Must |
| T-03 | ボタンは 768px 以上でのみ表示する（767px 以下では非表示） | Must |
| T-04 | `aria-expanded` が状態に追従し、アクセシブル名も「ファイルツリーを開く / 閉じる」で切り替わる | Must |
| T-05 | `aria-controls` がサイドバー本体の `id` を指すこと | Must |
| T-06 | 折りたたみ時、ツリー内のリンクがタブ順から外れること | Must |
| T-07 | 開閉にアニメーションを付けない | Should |

- T-07 は requirements.md §7.4「派手な演出はしない」に合わせる。パネル切替の 80ms フェードは本改修の対象外。
- 折りたたみ中はツリーから全ページへ到達できなくなるが、**既定が展開であり操作は可逆**なので
  requirements.md §7.6「タブがなくても全ページに到達できること」は初期状態で満たされる。

### 4.3 廃止する挙動

| 現行の挙動 | 廃止理由 |
|-----------|---------|
| 背景の暗幕（`bg-black/50`）とクリックでの閉じる操作 | 常設パネルはモーダルではない |
| 開いた瞬間に先頭リンクへフォーカスを移す処理 | 同上。フォーカスを奪うべきではない |
| Escape での閉じる処理 + トリガーへのフォーカス復帰 | 同上 |
| 1024px 以上になったら自動で閉じる `matchMedia` 監視 | 全幅で常設になるため不要 |

## 6. 技術方針

### 6.1 状態の持ち方

トグルの開閉状態は **DOM 属性で表現し、CSS で畳む**。

- トグルボタン（クライアントコンポーネント）が `useState` で自身の `aria-expanded` を管理し、
  クリック時にラッパー要素へ `data-sidebar="collapsed"` を付け外しする
- サイドバーの表示/非表示は CSS セレクタで解決する
- これにより `Sidebar` はサーバーコンポーネントのまま保て、React Context もクライアント境界の
  拡大も不要になる

> 代替案として開閉状態を Context で配ってサイドバーごとクライアント化する方法もあるが、
> ツリー全体がクライアント境界に入りバンドルと初期 HTML が増えるため採らない。

### 6.2 サイドバー幅のトークン化

`--spacing-sidebar` は現在 280px 固定。メディアクエリ内で再定義して 1 トークンのまま
レスポンシブにする（呼び出し側の `w-(--spacing-sidebar)` は変更不要）。ガター幅も同様に、
`.editor-row` の `grid-template-columns` を 1024px 未満で詰める。

### 6.3 影響ファイル

| ファイル | 変更内容 |
|---------|---------|
| `src/components/ide/Sidebar.tsx` | `hidden lg:block` → `hidden md:block`。`id` を付与し、折りたたみ用のセレクタ対象にする |
| `src/components/ide/SidebarToggle.tsx` | オーバーレイ一式（§4.3）を削除し、常設サイドバーの開閉トグルに作り替え。表示条件から `lg:hidden` を外す |
| `src/app/layout.tsx` | `data-sidebar` を受けるラッパーの配線 |
| `src/styles/globals.css` | `--spacing-sidebar` のレスポンシブ化、1024px 未満のガター詰め、折りたたみ用セレクタ |
| `docs/requirements.md` | §7.4 にトグル行を追加、§7.5 の表を §4.1 の内容に差し替え |
| `docs/CONTENT-TODO.md` | 「要件からの変更点」に3件目として追記 |

`FileTree.tsx` / `MobileIndex.tsx` / `TabBar.tsx` は変更しない。

### 6.4 requirements.md への反映

§7.5 の表を §4.1 のものに差し替え、既存の注記を以下に置き換える。

> 767px以下で無理にツリーを残すと、ただ使いにくいだけになる。「モバイルではIDEをやめる」を明示的な仕様とする。
> 一方 768px 以上では、モチーフである VS Code の「左にツリーが常駐する」構造を優先し、常設とする（[requirements-sidebar.md](./requirements-sidebar.md)）。

§7.4 の表に次の行を追加する。

| サイドバーのトグル | 常設サイドバーを畳む / 戻す。既定は展開。アニメーションなし |

## 7. 受け入れ条件

実装完了は以下をすべて満たした時点とする。

- [ ] 768 / 900 / 1023 / 1024 / 1280px の初期表示で、ツリーが左に見えている
- [ ] ツリーのファイルをクリックすると右のエディタが差し替わり URL が変わる。オーバーレイが閉じる挙動が存在しない
- [ ] トグルで折りたたみ / 展開ができ、`aria-expanded` とアクセシブル名が追従する
- [ ] 折りたたみ時、ツリー内のリンクが Tab 順から外れる
- [ ] 767px 以下の見た目と DOM が改修前と一致する（トグルボタンも非表示）
- [ ] 上記いずれの幅でも横スクロールが出ない
- [ ] `↑↓` `Home` `End` によるツリー内移動（F-14）が従来どおり動く
- [ ] Lighthouse デスクトップが 99 / 100 / 100 / 100 を下回らない
- [ ] `npm run lint` / `npm run typecheck` / `npm run build` が通る
- [ ] requirements.md §7.4 / §7.5 が実装と一致している
